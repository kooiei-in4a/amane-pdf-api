## 採用した初版

**会社名・宛先はnameLinesの明示配列へ改訂し、1〜2行・各20文字。会社住所も同じ上限。宛先の部署・担当者・敬称は完成した表示2行に含め、宛先住所の専用key／欄、独立した部署／担当者key、旧name形式との併存・自動移行は初版対象外。** 2行で足りない入力を短縮や省略で成功させない。範囲を将来広げる場合は別途判断・検証する。

| データ | 採用したkey・必須性 | 型・上限 | 表示先・責任 |
| --- | --- | --- | --- |
| 登録会社の表示名 | `nameLines`必須、旧`name`を置換 | string配列1〜2要素、各1〜20文字、LF結合後41文字以内 | issuer。会社名・拠点名などの帳票表示行を呼び出し元が完成させる。 |
| 登録会社の住所 | `addressLines`必須 | 同じ1〜2行・各20文字・LF込み41文字以内 | address。会社住所専用。宛先住所をここへ混ぜない。 |
| 発行時の宛先 | `recipient.nameLines`必須、旧`recipient.name`を置換 | 同じ1〜2行・各20文字・LF込み41文字以内 | recipient。会社名・部署・担当者・敬称を含む完成済み表示。会社登録とは別データ。 |
| 宛先住所 | 独立key／専用欄は初版対象外 | 許容上限はまだ設定しない | 現在の表示先と検証実績がない。必要なら専用欄を含む追加検証を先に行う。 |
| 宛先の部署・担当者 | 独立した`department`／`contactName`等のkeyは初版対象外 | nameLinesの2行予算内に含める場合だけ表示 | 3行目の追加や自動結合はしない。構造化入力が必要なら別判断。 |

「各20文字」はUTF-16 code unit。対応するBMP文字では通常1文字＝1 unit。**2行で40文字の内容＋LF1文字＝最大41文字**とし、各行の上限も別に検査する。会社名・会社住所・宛先の各欄に独立した2行予算があり、宛先名と部署／担当者は同じrecipientの2行を共有する。

- 1行だけの場合も配列1要素。自動改行・分割・短縮・trim・Unicode正規化・フォント縮小・敬称追加はしない。行順を保持してLF1つで結合する。
- 空配列、3行、空文字・全空白行、null・非string、各要素内のCR/LF・制御文字、未対応文字／禁止文字列等は拒否。前後空白も文字数と幅に含める。文字数・行数だけでなく、固定フォントと選択矩形への実幅／高さも検査する。
- 敬称も20文字に含む。御中／様を呼び出し元が必要に応じて完成させる。敬称の自動補完や重複修正はしない。
- 2行を使う長い会社名には、部署／担当者の追加行を保証しない。情報を削って成功させず、3行が必要なら明示拒否する。この制約を入力案内に明示する。
- 未実装の標準JSON案の改訂として、`name`／`recipient.name`との併存・自動移行は設けない。旧key、旧新keyの同時指定、未対応の宛先住所・部署・担当者keyはunknown-fieldとして明示拒否する候補。旧JSONは過去の検証再現用に残す。正式版の版識別・既存利用者への互換性が必要なら別途判断する。

登録会社の部分例（既存の長名PDFで描画済みの行）：

```json
{
  "nameLines": ["株式会社架空帳票研究開発センター", "東日本事業統括本部"],
  "addressLines": ["東京都架空区見本町一丁目二番地", "架空帳票研究開発試験センター第一棟"]
}
```

発行データの部分例（同じく描画済み）：

```json
{
  "recipient": {
    "nameLines": ["架空日本事業支援企画開発株式会社", "営業企画部 御中"]
  }
}
```

担当者宛ては、例えば第2行を`営業企画部 架空花子 様`とする考え方。これは配分の説明用で、資料提案時は未描画だったが、後続の[v0.3 roles](standard-json-v03-validation/README.md)で描画・抽出を確認済み。会社名・部署・担当者を別の情報として検索・管理するための登録モデルは今回設計しない。
