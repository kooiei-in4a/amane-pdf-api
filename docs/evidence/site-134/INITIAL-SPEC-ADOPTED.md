# #134 初版仕様 R1〜R8：採用記録

**ユーザーがR1〜R8を一括採用。仕様の採否は完了、製品未実装。採用後の[最終検証](standard-json-v03-final-validation/README.md)は正常24＋同時2／拒否135件で実施済み。** [採用前の提案](https://github.com/kooiei-in4a/amane-tools-site/issues/134#issuecomment-6352859912)を基に、採用内容をここへ固定する。既存の名称・数量・設定・取引／備考・罫線の採用は変更しない。

[標準JSON案v0.3](standard-json-draft-v0.3/README.md)を入力・表示仕様の基準、[最終検証一覧](FINAL-VALIDATION-site-134.md)を残作業の基準とする。過去のPDF・入力・スクリプト・測定は当時の条件の記録であり、採用後の再検証済みには読み替えない。既存PDF API契約の変更ではない。

**採用済み仕様は維持**：罫線整理、固定8明細・1ページ、数量文字列の整数部5桁・小数部3桁と末尾0保持、decimal／right、quantityAlignmentの既定・優先順位・不正登録拒否、nameLines／会社住所20文字×2行、宛先の部署・担当者・敬称を2行内に含めること、取引・備考共有3行／48文字と配分、請求書transaction必須／見積書任意。確定金額を再計算・上書きしない方針も維持します。

### R1 必須・任意項目

**採用仕様：現在のv0.3の項目表を初版の基準にする。**

| 区分 | 必須 | 任意・省略時 |
| --- | --- | --- |
| 登録会社 | nameLines、addressLines（採用済み） | registrationNumber、contact、bankTransferLines、logoAssetId、sealAssetId。省略は値と対応ラベルなし／画像なし。 |
| 発行共通 | companyId、templateId、currency、recipient.nameLines、issueDate、number、items（1〜8件）、taxSummary、totalAmount | quantityAlignmentは採用済み解決規則。subject、notesLinesは任意。 |
| 明細各件 | name、quantity、unitPrice、taxRate、amount | 未使用明細行は送らない。項目欠落を0や空文字で補完しない。 |
| 請求書 | transaction（採用済み） | paymentDueDateは任意。validUntilは拒否。 |
| 見積書 | 共通必須のみ | transaction（採用済み）、validUntilは任意。paymentDueDateは拒否。 |

numberは呼出元の確定番号（1〜16文字）で、採番・一意性検査なし。subject／contactは各1〜16文字、品名は1〜17文字（軽減記号を表示変換で付けた後は18文字以内）。registrationNumberはT＋ASCII数字13桁の形式検査のみ。振込先は請求書のみ適用する登録情報とし、各行16文字・最大3行かつLF込み48文字、見積書へ転用しません。日付は実在するYYYY-MM-DD、期間内の前後関係以外に発行日・期限との業務上の順序制約を追加しません。


### R2 税区分・通貨

**採用仕様：JPY・税抜入力、明細taxRateはJSON整数8／10のみ。** 8は軽減税率として既存の記号表示へ対応。非課税・免税・不課税・0%・外貨・税込入力は初版対象外として明示拒否します。サービスは税率の妥当性や税額を判定・算出しません。


### R3 金額の型・上限

**採用仕様：単価0〜99,999,999、明細金額・税率別対象額・税額・合計は各0〜999,999,999,999。** 金額は小数部・指数表記・符号のないJSON整数。文字列金額、小数、負数、指数表記、上限超過は拒否。カンマ・円表記は表示変換で付けます。

数量×単価、対象額×税率、明細合算、合計との相互整合性は検査しません。**型・範囲に合えば不一致も入力どおり表示**します。型検査だけでなく各欄の実幅も検査します。


### R4 数量0・負数

**採用仕様：数量は正数のみ。** 採用済み桁数・末尾0保持を維持し、"0"／"0.000"と負数を拒否。"0.001"等は受理。数値型、先頭＋、不要な先頭0、指数・カンマ・前後空白も拒否し、文字列を丸め・補正しません。


### R5 ゼロ表示・任意ラベル

**採用仕様：taxSummaryは"10"と"8"の両区分、それぞれtaxableAmount／taxAmountを必須とし、0も明示表示。** 該当なしでも呼出元が0を送ります。対象額・税額・明細金額・単価・合計の0を空欄へ変換せず、0円として表示。税率別の固定ラベルも残します。

任意項目は原則key省略とし、null・空文字は拒否。notesLinesの省略／[]は採用済みの「自由備考なし」。任意の件名・期限・登録情報等は省略時に値と対応ラベルを省きます。取引・備考の省略規則は採用済み仕様どおりです。


### R6 未対応文字・入力共通規則

**採用仕様：固定フォントの実際の対応文字表と矩形で事前検証。** UTF-16 unitで上限を数え、𠮷・絵文字・異体字セレクタ等の未対応文字、行内改行・制御文字、既存描画で解釈される%p／%P／%t／%v・バックスラッシュ直後のnを拒否。通常の%は許可。結合濁点・半濁点U+3099／U+309Aも初版は拒否し、合成済み文字への修正を案内します。PDF APIは結合濁点を受理して独立幅で描くため、これはsite側に置く採用制約です。

trim・Unicode正規化・代替文字・削除・自動折返し・縮小はしません。前後空白は保持して上限に含め、全空白は拒否。未知key・重複key・型の自動変換は拒否。登録／発行JSON本文はそれぞれUTF-8で64KiB以内を入口上限とします（画像は参照ID、本文へ埋め込まない）。


### R7 エラー形式・描画前拒否

**採用仕様：既存候補のJSON形式とJSON Pointerを採用。** 数量モードの採用済みstatus／code／source規則は変更しません。

- 400：壊れたJSON・重複key・未知key。
- 413：本文64KiB超過。
- 422：必須不足・型／値／桁数／文字／矩形の違反、不正登録値。
- 本文はstatus、code、errors配列。各要素にpath・code・修正理由message、必要に応じlimit／sourceを付ける。初版は**最初の1件だけ**を返し、複数集約は必須にしない。複数違反がある場合、どれを先に返すかは公開契約にしない。
- 登録不正は発行側の/companyIdまたは/templateIdと、source.kind／path／codeで直す登録項目を示す。正しい発行モードで不正登録モードを救済しない。

例（採用形式）：

~~~json
{
  "status": 422,
  "code": "validation-failed",
  "errors": [
    {
      "path": "/items/0/quantity",
      "code": "out-of-range",
      "message": "数量は0より大きい値を指定してください。"
    }
  ]
}
~~~

数量形式はquantity-format、型はinvalid-type、必須はrequired、金額範囲はout-of-range、不正な整数表記はinvalid-integer、文字はunsupported-character等、枠超過はfield-overflowを採用。数量モード等の採用済みcodeはそのまま。解析できない入力のpathは空文字（root）。入力値全文・内部fields index・内部例外は返しません。

**事前検証で拒否するケースは全体失敗・PDF API呼び出し0・部分PDFなし。** 事前検証後に起きたPDF API／通信障害は別であり、入力不正へ推測で付け替えません。認証・参照権限・混雑／timeout等のHTTP契約は後続の実装設計で決めます。


### R8 品質・時間・容量の受入基準

**採用仕様：以下を#134の検証受入基準にし、本番SLAとは区別する。**

| 観点 | 初版の受入基準 |
| --- | --- |
| PDF・文字 | 両帳票1／8明細・数量両モードは各1ページ、qpdf検査成功、入力から独立に作った期待値と全欄抽出一致。末尾0・確定金額保持、文字／画像の欠け・非意図的な重なりなし。decimal基準位置の誤差は0.1pt以内。 |
| 画像 | ロゴ・印影の透過／半透過・縦横比・配置・重ね順を確認。画像なしも確認。画像入力は既存上限1MiB／各辺2000px等を維持し、予約領域との非衝突も確認する。 |
| 時間 | 固定検証環境で、入力JSONの事前検証開始〜最終PDF受信まで、単独1チェーン10秒以内、同時2チェーンは各20秒以内。文字1回＋画像2回。起動・保存・抽出検査は除外し、条件を併記。 |
| 容量 | 最終1ページPDFは2MiB以内。画像あり・なしを分けて記録。 |
| 拒否・後始末 | 代表的な入力不正は元path付きで事前拒否・API呼び出し0。処理終了後のjob／子process残存なし。 |
| 閲覧 | Popplerの抽出・画像検査に加え、製品反映時は既存ブラウザプレビューで代表4帳票を確認。Acrobat・実印刷・site経由時間・他機能との資源競合は現時点で未確認として引き継ぐ。 |

根拠：CPU1・RAM1536MiB等の固定隔離Dockerで、v0.3正常18件は0.583〜1.136秒／217,277〜225,433 bytes。過去の同時2チェーンは各約1秒。**別時点の測定を、最新採用仕様の同時実行試験済みとは扱いません。** 10秒／20秒／2MiBは採用した受入値で、最大画像・site経由・本番の保証ではありません。最終採用条件で単独と既存共有2枠内の同時2チェーンを少数確認すればよく、長時間の負荷試験は不要です。



実際のHTTP応答・保存・認証は後続実装で確認する。IDの命名・版識別・認証／参照権限・混雑／timeoutの契約は今回の一括採用の範囲外。実印刷は#134を閉じる前の必須条件に追加せず未確認として引き継ぎ、製品反映時の既存ブラウザプレビュー確認を残す。
